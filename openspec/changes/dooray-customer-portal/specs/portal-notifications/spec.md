# portal-notifications

## ADDED Requirements

### Requirement: 브라우저 알림
고객은 두레이 계정이 없으므로, 포털이 폴링으로 변경을 감지해 브라우저에서 알림을 제공해야 한다(SHALL). 알림 대상: 새 업무 등록, 업무 상태 변경, 새 댓글.

#### Scenario: 운영팀 댓글 알림
- **WHEN** 운영팀이 두레이에서 댓글을 등록하고 다음 폴링이 실행되면
- **THEN** 헤더 벨에 미읽음 배지가 표시되고 드롭다운에 "새 댓글" 항목이 나타난다

#### Scenario: 상태 변경 알림
- **WHEN** 두레이에서 업무 상태가 변경되면
- **THEN** "상태 변경: 업무명 — 이전 → 현재" 알림이 생성된다

### Requirement: 본인 행동 알림 억제
사용자가 포털에서 직접 수행한 등록·댓글·상태 변경은 알림으로 표시해서는 안 된다(MUST NOT).

#### Scenario: 자기 댓글
- **WHEN** 사용자가 포털에서 댓글을 등록하면
- **THEN** 다음 폴링에서 해당 댓글에 대한 알림이 생성되지 않는다

### Requirement: 알림 상호작용
알림 항목 클릭 시 해당 업무 상세 모달이 열리고 그 항목은 읽음 처리되어야 한다(SHALL). "모두 읽음" 기능을 제공한다.

#### Scenario: 알림 클릭
- **WHEN** 드롭다운에서 알림을 클릭하면
- **THEN** 업무 상세 모달이 열리고 배지 카운트가 감소한다

### Requirement: OS 알림
사용자가 권한을 허용하고 탭이 백그라운드일 때는 브라우저 Notification API로 OS 알림을 발송해야 한다(SHALL). 권한 요청은 벨 첫 클릭 시 수행한다.

#### Scenario: 백그라운드 알림
- **WHEN** 권한 허용 상태에서 탭이 숨겨져 있고 새 알림이 생기면
- **THEN** OS 알림이 표시된다
